\section{ePATH Test Bench}


\subsection{Overview}
The purpose of this project is to check that the PCB board of ePATH functions properly. This would help ensure that it was properly manufactured by the factory and it will help smooth identification of faults during maintenance. The process must be automated and user-friendly to enable any technician without in-depth knowledge of the electronics of ePATH to perform this test. 

The different components of the testing system and their interactions are briefly introduced in Figure \ref{end_goal_diagram}.


\begin{figure}[H]

          \caption{Overview of design aspects ePATH testing software.}
          \label{end_goal_diagram}

The specific objectives of ePATH Test Bench project were: 
\begin{itemize}
\item To establish communication between a computer and a multimeter so that any measurements made from the ePATH PCB can easily be processed by the computer to check whether they are as expected.
\item To design a custom PCB board that selects the appropriate pin from the ePATH board to be tested. Since the ePATH board consists of 2 different grounds, it should accommodate for this by selecting the correct one for each measurement.
\item To develop a GUI that offers an interactive way to do the test.
\item To produce a pdf file with a summary of all the testing results.
\end{itemize}


\subsection{Multimeter connection}
Establishing communication between the computer, Arduino, and multimeter proved to be a challenge. Originally, the goal was to use the oscilloscope RIGOL MSO1104 Z but we couldn't find the driver needed to connect it to the computer. Eventually, we ended up using the multimeter Agilent 34401A 61/2 Digit Multimeter\cite{keysight34401A}. 

The most prominent difficulty was that the multimeter received commands but did not transmit anything back. For example, when sending a MEAS:VOLT:DC? command, the voltage was displayed on the multimeter screen but not sent to the computer. This was resolved after adjusting the MAX3232 connector. A 3.5kOhm pull-up resistor was utilized and connected as shown in Figure \ref{MAX3232}.

\subsection{PCB version 1}
After some prototyping with a breadboard, the first version of the PCB was developed that was compatible with an Arduino DUE. It was given the name 'Automated DMM tester V1'. The purpose of this version is to test everything works smoothly and identify areas of improvement. 

The kiCAD design of the PCB is stored in the resources folder under PCB attempt 1. The Arduino program used to test the functionality of the PCB is saved in the resources folder under PCB programming.

A 16 channel multiplexer (MUX) was chosen to direct the current from each ePATH test point to the multimeter so that the tests can be performed. A MUX was chosen over alternatives, such as shift registers, for its simple wiring and fast operation \cite{tiMAX3232guide}. A 16 channeled one was chosen as there are 12 pins to be tested.

In the schematic, the $330\,\Omega$ resistors were chosen since the forward voltage drop for white LEDs is approximately 2.4V and the desired current flow through them is about 10mA. Therefore:
\[
R = \frac{V}{I} = \frac{5\,\mathrm{V} - 2.4\,\mathrm{V}}{10\,\mathrm{mA}}=260\Omega
\]
Since $330\,\Omega$ is very close to the desired resistance and is a more readily available resistor value it was chosen for the schematic. 

When soldering the components on the board some alterations were made; instead of $330\,\Omega$ resistors, $1.6k\,\Omega$ resistors were used and instead of $10k\,\Omega$ resistors $4.6k\,\Omega$ resistors were used. These resistor values proved to make the system work well.

There were a number of errors with this design:
\begin{itemize}
\item The footprint used for the banana socket is wrong. It only has a hole for the cental pin of the socket but not for the other 4 pins. This led to receiving an inquiry about it from the PCB manufacturers but this was easily resolved.
\item The orientation of the button footprint is incorrect-it should be rotated by 90 degrees. This issue was bypassed when making the button connection to the board.
\item When testing the PCB with the ePATH board it was discovered that upon trying to measure negative voltages it stopped working. It was established that it can measure a minimum voltage of around -0.5V. Therefore, a different MUX capable of enabling negative voltage measurements should have been used.
\item The wiring of the Restart button is incorrect. It was not connected to the Arduino DUE pin 8 properly. This was corrected on the board by adding a wire according to the diagram in Figure \ref{button_wiring}.
\end{itemize}

\subsection{PCB version 2}
The second version of the PCB was given the name 'Automated DMM tester V2-July 2025'. The purpose of this version is to perform some tests with ePATH and explore a different combination of electrical components. The improvements made for this version include:
\begin{itemize}
\item To facilitate the connection between the test points on ePATH with the PCB, a D-sub connector was implemented.
\item The PN532 module capable of obtaining the RFID tag of the ePATH board was implemented.
\item Instead of using a multiplexer, shift registers and relays were used. That's because relays are optically isolated which minimizes noise. 
\item Since the number of electrical components being controlled by the Arduino increased in this PCB iteration, an external voltage source was required; the PCB could no longer be powered by the Arduino. For that reason a 5V voltage regular was implemented.
\item Since the ePATH board has 2 grounds a control system to switch between them was implemented.
\item A digital potentiometer was implemented to produce the resistances needed for some of the ePATH board tests.
\end{itemize}

To enhance my understanding of shift register operation I wired up the relays and shift registers in TinkerCad and ran some simulations. The simulation is stored in the resources folder under Shift registers sim. An important aspect of the software is sending the appropriate commands to the appropriate relays especially because of the unordered connections. The excel file used to work out the correct command order is in the resources folder under Shift register bytes. The Arduino IDE code I used to check that the correct relays on the PCB are activated for troubleshooting is in the resources folder under relay test.

The kiCAD design of the PCB is stored in the resources folder under PCB attempt 2. In the schematic, the $620\,\Omega$ resistors were chosen since the shift registers output 5V and a current of 8mA. A 1V is sufficient to turn the relay on. Therefore:
\[
R = \frac{V}{I} = \frac{5\,\mathrm{V} - 1\,\mathrm{V}}{8\,\mathrm{mA}}=500\Omega
\]
Since $620\,\Omega$ is very close to the desired resistance and is a more readily available resistor value it was chosen for the schematic.

According to the LM1085IS-ADJNOPB voltage regulator documentation the following equation applies when in the adjustable setting:
$V_{out} = V_{ref} \left( 1 + \frac{R_2}{R_1} \right)$.
Since $V_{\text{OUT}} = 5\,\text{V}$ and a typical $V_{\text{REF}} = 1.25\,\text{V}$, the ratio $\frac{R_2}{R_1}$ equals 3. This is the reason a $10\,\text{k}\Omega$ and a $30\,\text{k}\Omega$ resistor were used in the schematic. However, upon examining the documentation more closely it was discovered that the equation used only applies when $R_1$ is around $100\,\Omega$. When that is not the case this equation applies:
$$V_{\text{OUT}} = V_{\text{REF}} \left( 1 + \frac{R_2}{R_1} \right) + I_{\text{ADJ}} R_2$$
Therefore, the $I_{\text{ADJ}}$ term introduces an output error. For that reason $120\,\Omega$ and $360\,\Omega$ resistors were used on the PCB to produce the correct voltage output.

\subsection{PCB version 3}
The third version of the PCB was given the name 'Automated DMM tester V3-August 2025'. The only corrections to this version are the ASSR-1420-302E relay footprint and the wiring to the U2 relay that controls resistance implementatio from the potentiometer. The kiCAD design of the PCB is stored in the resources folder under PCB attempt 3. The Arduino code used to control the PCB is stored in the resources folder under PCB3 programming.

This version of the PCB showed satisfactory performance. However, there are always possible improvements some of which include:
\begin{itemize}
\item Currently, the user must manually connect all test points from the PCB to the ePATH board, a process that is both time-consuming and prone to creating tangled wiring. An alternative connection method could be explored—for instance, developing an additional PCB that can be mounted directly onto the ePATH board to interface with the test points more efficiently.
\item Some tests like the switching and inverted signal tests need to be done manually by the user and are not part of the automated process yet. These should also be automated to make the system optimal. In order to achieve this establishing a computer-oscilloscope communication is required.
\end{itemize}

\subsection{GUI}
A user friendly GUI has been developed to facilitate the testing of the ePATH board. The code for the GUI is on the ePATH-Test-Bench project of the company's GitHub \href{https://github.com/pathfinder-medical/ePATH-Test-Bench}{here}. To be able to run the code of ensure that all required modules are installed and that the directories at the start of the script are correct. This GUI is compatible with the Arduino code of all PCBs.

The key functionalities of the GUI include:
\begin{itemize}
\item Run button; Starts the testing cycle. During testing, this button is converted into a Stop button that interrupts the testing cycle.
\item Clear button; Deletes all testing results for re-tests.
\item Save button; Saves a pdf file with the table of results.
\item Get RFID button; Gets the RFID of the ePATH board using the PN532 module.
\end{itemize}
